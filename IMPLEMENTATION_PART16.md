# Часть 16: Админское управление промптами

## Обзор

Реализована система администрирования LLM промптов с полной историей изменений и возможностью отката к любой предыдущей версии. Это позволяет гибко настраивать поведение LLM без необходимости перезапуска приложения.

## Backend

### Эндпоинты

#### GET /admin/prompts

Возвращает список всех промптов (только метаданные, без текста шаблона).

**Параметры:** нет

**Ответ:**
```json
[
  {
    "key": "generate_sentences",
    "updated_at": "2024-01-15T10:30:00Z",
    "updated_by": 1
  },
  {
    "key": "evaluate_translation",
    "updated_at": "2024-01-14T15:20:00Z",
    "updated_by": 1
  }
]
```

#### GET /admin/prompts/{key}

Возвращает полную информацию о промпте включая текст шаблона.

**Параметры:**
- `key` (string) - ключ промпта

**Ответ:**
```json
{
  "key": "generate_sentences",
  "system_template": "Generate {count} sentences for {level} level...",
  "required_placeholders": ["level"],
  "updated_at": "2024-01-15T10:30:00Z",
  "updated_by": 1
}
```

**Ошибки:**
- `404 prompt_not_found` - промпт не найден

#### PUT /admin/prompts/{key}

Обновляет промпт с полной валидацией и сохранением в историю.

**Параметры:**
- `key` (string) - ключ промпта

**Тело запроса:**
```json
{
  "system_template": "New template with {level} placeholder"
}
```

**Ответ:** Обновлённый промпт (как в GET)

**Валидация:**
1. Ключ должен быть из фиксированного списка (`generate_sentences`, `evaluate_translation`)
2. Длина шаблона: 1-8000 символов
3. Извлечение всех плейсхолдеров `{name}` (игнорируя `{{` и `}}`)
4. Проверка, что все найденные плейсхолдеры разрешены
5. Проверка, что все обязательные плейсхолдеры присутствуют
6. Тестовый рендеринг шаблона через `str.format_map`

**Ошибки:**
- `404 prompt_not_found` - неизвестный ключ
- `422 unknown_placeholder` - неразрешённый плейсхолдер
- `422 missing_placeholder` - отсутствует обязательный плейсхолдер
- `422 invalid_template` - синтаксическая ошибка шаблона

**Правила плейсхолдеров:**
- `generate_sentences`: разрешён только `{level}`
- `evaluate_translation`: нет разрешённых плейсхолдеров

#### GET /admin/prompts/{key}/history

Возвращает историю изменений промпта с пагинацией.

**Параметры:**
- `key` (string) - ключ промпта
- `page` (int, default: 1) - номер страницы
- `page_size` (int, default: 20, max: 100) - размер страницы

**Ответ:**
```json
{
  "items": [
    {
      "id": 5,
      "system_template": "Template version 5",
      "created_at": "2024-01-15T10:30:00Z",
      "created_by": 1
    }
  ],
  "total": 5,
  "page": 1,
  "page_size": 20
}
```

#### POST /admin/prompts/{key}/rollback

Откатывает промпт к указанной версии из истории.

**Параметры:**
- `key` (string) - ключ промпта

**Тело запроса:**
```json
{
  "history_id": 3
}
```

**Ответ:** Обновлённый промпт (как в GET)

**Особенности:**
- Валидирует исторический шаблон так же, как при обычном сохранении
- Создаёт новую запись в истории (история никогда не удаляется)
- Атомарная транзакция

**Ошибки:**
- `404 prompt_not_found` - неизвестный ключ
- `404 history_not_found` - версия истории не найдена

### Безопасность

#### Фиксированные ключи

Конфигурация в `backend/app/services/admin_prompts_service.py`:

```python
ALLOWED_PROMPT_KEYS = {"generate_sentences", "evaluate_translation"}
```

Админ не может создавать новые промпты или удалять существующие.

#### Валидация плейсхолдеров

Конфигурация разрешённых плейсхолдеров:

```python
PROMPT_PLACEHOLDERS = {
    "generate_sentences": {
        "required": {"level"},
        "allowed": {"level"},
    },
    "evaluate_translation": {
        "required": set(),
        "allowed": set(),
    },
}
```

#### Извлечение плейсхолдеров

```python
def _extract_placeholders(self, template: str) -> Set[str]:
    # Заменяем экранированные скобки
    temp = template.replace("{{", "\x00").replace("}}", "\x01")
    # Находим все {name} паттерны
    pattern = r"\{([^{}]+)\}"
    matches = re.findall(pattern, temp)
    return set(matches)
```

#### Тестовый рендеринг

```python
TEST_VALUES = {
    "generate_sentences": {"level": "B1"},
    "evaluate_translation": {},
}

# Проверяем, что шаблон можно отрендерить
template.format_map(TEST_VALUES[key])
```

### Транзакционность

Обновление промпта выполняется атомарно:

```python
async with self.session.begin():
    # 1. Вставляем в историю
    history_entry = PromptHistory(...)
    self.session.add(history_entry)
    
    # 2. Обновляем текущий промпт
    prompt.system_template = system_template
    prompt.updated_at = datetime.now(timezone.utc)
    prompt.updated_by = self.admin.id
```

## Frontend

### Страница AdminPromptsPage

**Расположение:** `/admin/prompts`

**Функциональность:**

1. **Список промптов**
   - Отображает все доступные промпты
   - Показывает дату последнего изменения
   - Показывает автора последнего изменения
   - Клик по промпту открывает детали

2. **Детали промпта**
   - Полный текст шаблона
   - Обязательные плейсхолдеры
   - Информация о последнем изменении
   - Кнопка "Редактировать"

3. **Редактирование**
   - Текстовый редактор для шаблона
   - Кнопки "Сохранить" и "Отмена"
   - Валидация на стороне сервера
   - Отображение ошибок валидации

4. **История изменений**
   - Список всех версий (новые сверху)
   - Текст каждой версии
   - Дата и автор изменения
   - Кнопка "Откатить" для каждой версии
   - Пагинация (10 версий на странице)

✅ Промпт с неизвестным плейсхолдером отклоняется  
✅ Промпт без обязательного плейсхолдера отклоняется  
✅ Невалидный шаблон не записывается  
✅ После сохранения следующий LLM-вызов использует новый текст  
✅ Откат восстанавливает старый текст  
✅ Откат добавляет новую запись в историю, а не удаляет старую  
✅ История никогда не удаляется  
✅ Нельзя создать новый промпт  
✅ Нельзя удалить существующий промпт  
✅ Все изменения логируются с указанием автора  
✅ Фронтенд корректно отображает ошибки валидации  
✅ Фронтенд позволяет редактировать и откатывать промпты  

## Архитектурные решения

### Почему фиксированные ключи?

- **Безопасность:** предотвращает создание произвольных промптов
- **Контроль:** все промпты известны и документированы
- **Простота:** не нужна система управления метаданными промптов

### Почему валидация на уровне синтаксиса?

- **Безопасность:** не выполняем реальные вызовы LLM при сохранении
- **Скорость:** мгновенная валидация без внешних вызовов
- **Достаточность:** синтаксические ошибки ловятся, семантика проверяется при использовании

### Почему история не удаляется?

- **Аудит:** полная история всех изменений
- **Откат:** возможность вернуться к любой версии
- **Прозрачность:** видно, кто и когда менял промпт

### Почему транзакционность?

- **Целостность:** история и текущая версия всегда синхронизированы
- **Надёжность:** при ошибке оба изменения откатываются
- **Атомарность:** нет промежуточных состояний

## Ограничения

1. **Фиксированные ключи:** нельзя создать новые промпты через админку
2. **Ограниченные плейсхолдеры:** только предопределённые имена
3. **Длина шаблона:** максимум 8000 символов
4. **Нет тестового вызова:** валидация только синтаксическая
5. **История растёт:** нет механизма очистки старой истории

## Использование в рантайме

Промпты читаются из БД перед каждым LLM вызовом:

```python
# В PromptService
async def get_prompt(self, key: str) -> str:
    result = await self.session.execute(
        select(Prompt).where(Prompt.key == key)
    )
    prompt = result.scalar_one_or_none()
    
    if prompt is None:
        logger.critical(f"prompt_missing: {key}")
        return FALLBACK_PROMPTS[key]
    
    return prompt.system_template
```

Изменения вступают в силу немедленно для следующих вызовов. Уже идущие вызовы не затрагиваются.
