# ✅ Реализовано автоматическое перенаправление на страницу авторизации

## Что было сделано

Создан компонент `ProtectedRoute`, который автоматически перенаправляет неавторизованных пользователей на страницу `/auth` вместо показа сообщения "Требуется авторизация".

## Изменения

### 1. Создан компонент ProtectedRoute

**Файл:** `src/components/ProtectedRoute.tsx`

```typescript
const ProtectedRoute: React.FC<ProtectedRouteProps> = ({ children }) => {
  const { isAuthenticated, isLoading } = useAuth();
  const location = useLocation();

  // Show loading screen while checking authentication
  if (isLoading) {
    return <LoadingScreen />;
  }

  // Redirect to auth if not authenticated
  if (!isAuthenticated) {
    return <Navigate to="/auth" state={{ from: location }} replace />;
  }

  return <>{children}</>;
};
```

**Особенности:**
- ✅ Показывает экран загрузки во время проверки авторизации
- ✅ Автоматически перенаправляет на `/auth` если пользователь не авторизован
- ✅ Сохраняет исходный маршрут в `state.from` для возможного возврата после авторизации
- ✅ Использует `replace` для замены истории навигации

### 2. Обновлены маршруты в App.tsx

**Файл:** `src/App.tsx`

Все защищенные маршруты обернуты в `ProtectedRoute`:

```typescript
<Routes>
  {/* Public routes */}
  <Route path="/auth" element={<AuthPage />} />
  
  {/* Protected routes */}
  <Route path="/" element={<ProtectedRoute><HomePage /></ProtectedRoute>} />
  <Route path="/onboarding" element={<ProtectedRoute><OnboardingPage /></ProtectedRoute>} />
  <Route path="/dictionary" element={<ProtectedRoute><DictionaryPage /></ProtectedRoute>} />
  <Route path="/profile" element={<ProtectedRoute><ProfilePage /></ProtectedRoute>} />
  {/* ... и все остальные маршруты */}
</Routes>
```

## Как это работает

### Сценарий 1: Пользователь не авторизован

```
1. Пользователь открывает http://localhost:3000/
   ↓
2. AuthContext проверяет наличие токена
   ↓
3. Токен отсутствует (isAuthenticated = false)
   ↓
4. ProtectedRoute перенаправляет на /auth
   ↓
5. Пользователь видит страницу авторизации ✅
```

### Сценарий 2: Пользователь авторизован

```
1. Пользователь открывает http://localhost:3000/
   ↓
2. AuthContext проверяет наличие токена
   ↓
3. Токен присутствует (isAuthenticated = true)
   ↓
4. ProtectedRoute рендерит HomePage
   ↓
5. Пользователь видит главную страницу ✅
```

### Сценарий 3: Попытка доступа к защищенной странице

```
1. Пользователь пытается открыть http://localhost:3000/dictionary
   ↓
2. ProtectedRoute проверяет авторизацию
   ↓
3. Пользователь не авторизован
   ↓
4. Перенаправление на /auth с сохранением /dictionary в state.from
   ↓
5. После авторизации можно вернуть пользователя на /dictionary ✅
```

## Технические детали

### Защищенные маршруты

Все маршруты кроме `/auth` защищены:
- `/` - главная страница
- `/onboarding` - онбординг
- `/dictionary` - личный словарь
- `/profile` - профиль
- `/lesson/*` - все страницы уроков
- `/vocabulary/*` - словарь слов
- `/settings` - настройки
- `/learning-profile` - настройки обучения
- `/admin/*` - админ-панель

### Публичные маршруты

Только `/auth` доступен без авторизации:
- `/auth` - страница входа/регистрации

### Экран загрузки

Пока проверяется авторизация, показывается экран загрузки:
```
⏳
Загрузка...
```

Это предотвращает "мигание" интерфейса при проверке токена.

## Дополнительные улучшения

### Возврат после авторизации

Можно реализовать возврат на исходную страницу после успешной авторизации:

```typescript
// В AuthPage после успешного входа:
const location = useLocation();
const from = location.state?.from?.pathname || "/";
navigate(from);
```

Это улучшит UX, если пользователь пытался получить доступ к защищенной странице.
