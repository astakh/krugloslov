# Часть 14: Админ-панель - Жалобы и управление пользователями

Реализована функциональность административной панели для управления жалобами пользователей и сброса паролей.

## Backend

### Новые эндпоинты

#### 1. GET /admin/reports

Получение списка жалоб пользователей с фильтрацией и пагинацией.

**Параметры:**
- `status` (опционально): фильтр по статусу (new/processed)
- `page` (по умолчанию 1): номер страницы
- `page_size` (по умолчанию 20, макс 100): количество элементов на странице

**Ответ:**
```json
{
  "reports": [
    {
      "id": 1,
      "user_id": 5,
      "user_email": "user@example.com",
      "exercise_id": 42,
      "target_sentence": "The cat runs fast.",
      "reference_translation": "Кот бегает быстро.",
      "user_translation": "Кошка бежит быстро.",
      "target_words": [
        {
          "word_id": 10,
          "lemma": "run",
          "pos": "verb",
          "surface_form": "runs"
        }
      ],
      "reason": "wrong_translation",
      "comment": "Перевод неточный",
      "status": "new",
      "admin_note": null,
      "created_at": "2024-01-15T10:30:00Z",
      "llm_call_ids": [123, 124]
    }
  ],
  "total": 15,
  "page": 1,
  "page_size": 20
}
```

**Особенности:**
- Возвращает полную информацию об упражнении
- Включает целевые слова с surface_form
- Показывает связанные LLM вызовы
- Сортировка по дате создания (новые первые)

#### 2. PATCH /admin/reports/{report_id}

Обработка жалобы администратором.

**Запрос:**
```json
{
  "status": "processed",
  "admin_note": "Перевод корректный, жалоба отклонена"
}
```

**Ответ:**
```json
{
  "message": "Report processed successfully",
  "report_id": 1
}
```

**Особенности:**
- Переход только из new в processed
- Идемпотентность: повторная обработка с теми же данными возвращает успех
- admin_note сохраняется и может быть обновлён
- Действие логируется в events с типом `admin_process_report`

#### 3. GET /admin/users

Получение списка пользователей с поиском и пагинацией.

**Параметры:**
- `search` (опционально): поиск по email (case-insensitive)
- `page` (по умолчанию 1): номер страницы
- `page_size` (по умолчанию 20, макс 100): количество элементов на странице

**Ответ:**
```json
{
  "users": [
    {
      "id": 1,
      "email": "user@example.com",
      "is_onboarded": true,
      "is_admin": false,
      "created_at": "2024-01-01T10:00:00Z"
    }
  ],
  "total": 150,
  "page": 1,
  "page_size": 20
}
```

**Особенности:**
- Поиск по email без учёта регистра
- НЕ возвращает password_hash и токены
- Сортировка по дате создания (новые первые)

#### 4. POST /admin/users/{user_id}/reset-password

Сброс пароля пользователя администратором.

**Ответ:**
```json
{
  "message": "Password reset successfully",
  "user_id": 5,
  "temporary_password": "aB3$xY9!mN2@"
}
```

**Особенности:**
- Генерирует безопасный временный пароль (12+ символов)
- Пароль содержит буквы разного регистра, цифры и спецсимволы
- Пароль показывается ТОЛЬКО ОДИН РАЗ
- Все refresh токены пользователя отзываются
- Нельзя сбросить свой собственный пароль
- Действие логируется в events с типом `admin_reset_password`

**Ошибки:**
- 404 `user_not_found` - пользователь не найден
- 400 `cannot_reset_own_password` - попытка сбросить свой пароль

### Сервисы

#### AdminReportsService (`backend/app/services/admin_reports_service.py`)
- `get_reports()` - получение списка жалоб с фильтрацией
- `process_report()` - обработка жалобы с валидацией переходов
- `_build_report_item()` - сборка полной информации о жалобе
- `_log_admin_action()` - логирование действий администратора

#### AdminUsersService (`backend/app/services/admin_users_service.py`)
- `get_users()` - получение списка пользователей с поиском
- `reset_password()` - сброс пароля с отзывом сессий
- `_generate_temporary_password()` - генерация безопасного пароля
- `_log_admin_action()` - логирование действий администратора

## Безопасность

### Защита эндпоинтов
- Все эндпоинты требуют `is_admin = true`
- Используется зависимость `require_admin`
- Возвращается 403 для не-администраторов

### Сброс пароля
- Генерация криптографически безопасного пароля
- Пароль содержит минимум 12 символов
- Обязательное наличие букв разного регистра, цифр и спецсимволов
- Пароль показывается только один раз
- Все сессии пользователя отзываются немедленно
- Нельзя сбросить свой собственный пароль

### Логирование
- Все действия администратора логируются в таблицу events
- Типы событий: `admin_process_report`, `admin_reset_password`
- Логи включают: admin_id, target_id, детали действия, временную метку

### Защита данных
- НЕ возвращаются password_hash
- НЕ возвращаются refresh токены
- НЕ возвращаются хэши токенов
- Поиск по email без раскрытия других данных

## Проверка функциональности

### Backend

```bash
# Получить список жалоб
curl -X GET "http://localhost:8000/admin/reports?page=1&page_size=20" \
  -H "Authorization: Bearer <admin_token>"

# Обработать жалобу
curl -X PATCH "http://localhost:8000/admin/reports/1" \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "processed",
    "admin_note": "Жалоба обработана"
  }'

# Получить список пользователей
curl -X GET "http://localhost:8000/admin/users?search=user&page=1" \
  -H "Authorization: Bearer <admin_token>"

# Сбросить пароль пользователя
curl -X POST "http://localhost:8000/admin/users/5/reset-password" \
  -H "Authorization: Bearer <admin_token>"
```
