# Часть 15: Админский просмотр базы данных

## Обзор

Реализован админский интерфейс для просмотра содержимого базы данных в режиме "только чтение". Это позволяет администраторам исследовать данные, отлаживать проблемы и проверять состояние системы без риска случайного изменения данных.

## Backend

### Эндпоинты

#### GET /admin/db/tables

Возвращает список всех пользовательских таблиц с приблизительным количеством строк.

**Параметры:** нет

**Ответ:**
```json
[
  {
    "table_name": "users",
    "row_count_estimate": 120,
    "columns_count": 8
  },
  {
    "table_name": "words",
    "row_count_estimate": 5420,
    "columns_count": 6
  }
]
```

**Особенности:**
- Использует `pg_class.reltuples` для быстрого приближённого подсчёта строк
- Исключает технические таблицы (alembic_version)
- Сортирует по имени таблицы

#### GET /admin/db/tables/{table_name}

Возвращает постраничные данные таблицы с возможностью сортировки и поиска.

**Параметры:**
- `page` (int, default: 1) - номер страницы
- `page_size` (int, default: 25, max: 100) - размер страницы
- `order_by` (string, optional) - имя столбца для сортировки
- `order_dir` (string, default: "asc") - направление сортировки (asc/desc)
- `search` (string, optional) - поисковый запрос

**Ответ:**
```json
{
  "table_name": "users",
  "columns": [
    {
      "name": "id",
      "type": "integer",
      "is_primary_key": true,
      "masked": false
    },
    {
      "name": "password_hash",
      "type": "character varying",
      "is_primary_key": false,
      "masked": true
    }
  ],
  "rows": [
    {
      "id": 1,
      "email": "user@example.com",
      "password_hash": "••••••••"
    }
  ],
  "page": 1,
  "page_size": 25,
  "total": 120
}
```

**Особенности:**
- Маскирует чувствительные данные (password_hash, token_hash) на уровне SQL
- Использует `psycopg.sql.Identifier` для безопасной подстановки имён
- Поддерживает поиск по всем текстовым столбцам (ILIKE)
- Таймаут 5 секунд для COUNT(*) запроса

### Безопасность

#### Маскирование чувствительных данных

Конфигурация в `backend/app/services/admin_db_service.py`:

```python
SENSITIVE_COLUMNS: Set[Tuple[str, str]] = {
    ("users", "password_hash"),
    ("refresh_tokens", "token_hash"),
}
```

Маскирование выполняется на уровне SQL:
```sql
CASE WHEN true THEN '••••••••' ELSE password_hash END
```

Это гарантирует, что реальные значения никогда не покидают базу данных.

#### Безопасная подстановка идентификаторов

Все имена таблиц и столбцов подставляются через `psycopg.sql.Identifier`:

```python
from psycopg import sql

table_ident = sql.Identifier(table_name)
column_ident = sql.Identifier(column_name)

query = sql.SQL("SELECT {} FROM {}").format(column_ident, table_ident)
```

Это предотвращает SQL-инъекции через имена таблиц/столбцов.

#### Валидация

1. **Существование таблицы:** проверка через `information_schema.tables`
2. **Существование столбца:** проверка через `information_schema.columns`
3. **Допустимые значения order_dir:** только "asc" или "desc"
4. **Ограничения page_size:** от 1 до 100

### Исключения

- `404 table_not_found` - таблица не существует
- `422 invalid_order_by` - столбец для сортировки не существует
- `422 invalid_order_dir` - недопустимое направление сортировки
- `422 invalid_page_size` - размер страницы вне диапазона

## Frontend

### Страница AdminDbPage

**Расположение:** `/admin/db`

**Функциональность:**

1. **Список таблиц**
   - Отображает все пользовательские таблицы
   - Показывает приблизительное количество строк
   - Показывает количество столбцов
   - Клик по таблице открывает её содержимое

2. **Просмотр таблицы**
   - Таблица с данными
   - Сортировка по клику на заголовок столбца
   - Индикаторы: 🔑 для первичного ключа, 🔒 для замаскированных столбцов
   - Пагинация (25 записей на странице)
   - Поиск по текстовым столбцам

3. **Отображение данных**
   - NULL значения отображаются курсивом
   - Замаскированные значения показываются как `••••••••`
   - Длинные значения (>50 символов) обрезаются с кнопкой "Показать"
   - JSON данные форматируются с отступами

### Навигация

Добавлена кнопка "База данных" в админ-панель:
- Расположение: `/admin`
- Переход: `/admin/db`

## Архитектурные решения

### Почему приближённый подсчёт строк?

Использование `pg_class.reltuples` вместо `COUNT(*)` для списка таблиц:
- **Скорость:** мгновенный результат vs секунды для больших таблиц
- **Достаточно для UI:** пользователю важен порядок величины, не точное число
- **Нагрузка:** не создаёт нагрузку на базу данных

### Почему маскирование на уровне SQL?

- **Безопасность:** данные никогда не покидают БД в открытом виде
- **Производительность:** не нужно обрабатывать данные в Python
- **Надёжность:** невозможно случайно отправить реальные данные

### Почему psycopg.sql.Identifier?

- **Безопасность:** автоматическое экранирование имён
- **Стандарт:** официальный способ подстановки идентификаторов
- **Защита от инъекций:** невозможно внедрить SQL через имена таблиц/столбцов

### Почему таймаут 5 секунд для COUNT(*)?

- **UX:** пользователь не должен ждать слишком долго
- **Реальность:** для очень больших таблиц COUNT(*) может быть медленным
- **Компромисс:** если не успели - возвращаем `total: null`, пагинация всё равно работает

## Ограничения

1. **Только чтение:** нет возможности редактировать или удалять данные
2. **Нет произвольного SQL:** только предопределённые запросы
3. **Поиск только по текстовым столбцам:** числовые столбцы не поддерживаются
4. **Таймаут COUNT(*):** для очень больших таблиц может вернуть `total: null`
5. **Приблизительный подсчёт:** `row_count_estimate` может отличаться от реального
